Проверьте и доставьте:

sh
ps aux | grep -i pipewire        # запущены ли pipewire и wireplumber
sudo xbps-install pipewire wireplumber libspa-alsa

PipeWire на Void не стартует сам — его нужно автозапускать в сессии. Добавьте в ~/.config/niri/config.kdl:

kdl
spawn-at-startup "pipewire"
spawn-at-startup "pipewire-pulse"
spawn-at-startup "wireplumber"

(либо, что чище, включите их как пользовательские сервисы — но для начала spawn-at-startup проще). pipewire-pulse — это и есть Pulse-совместимый слой, ради которого pavucontrol заработает.

После перезапуска сессии проверьте: pactl info — должно показать сервер PipeWire. Тогда и pavucontrol подключится, и звук пойдёт.

Но, честно говоря, pavucontrol вам, возможно, и не нужен — у noctalia в панели уже есть регулятор громкости (тот значок динамика в трее на вашем скриншоте). Через него громкость и устройства вывода настраиваются без отдельной утилиты. pavucontrol нужен, только если хочется тонко рулить потоками приложений.

Скриншот без клавиши PrtScr. На вашем Asus её нет физически — частая история на ноутбуках. Два выхода:

Повесьте скриншот на другую клавишу. В ~/.config/niri/config.kdl замените строку Print { screenshot; } на удобное сочетание, например:
kdl
   Mod+Print { screenshot; }
   Mod+S { screenshot; }

(но Mod+S у вас может быть занят под noctalia — проверьте). Или используйте Mod+Shift+S.
2. Проверьте Fn-комбинацию. На многих Asus PrtScr спрятан под Fn + одна из F-клавиш (часто Fn+F... со значком ножниц/камеры). Посмотрите на верхний ряд — там может быть иконка скриншота.

Скриншоты niri делает своим встроенным UI — после нажатия появится рамка выделения, дальше Enter/Space сохранит.

Amnezia — GUI не открывается, хотя служба жива. Ваш ps показал: сервис amnezia-vpn и демон AmneziaVPN-service работают. То есть背 end живёт, а не запускается именно окно (GUI). Причина почти наверняка в том, что GUI — это отдельное приложение, и оно либо не находит Wayland-дисплей, либо падает молча. Запустите его из терминала внутри niri, чтобы увидеть ошибку:

sh
ls /opt/AmneziaVPN/
/opt/AmneziaVPN/AmneziaVPN     # или /opt/AmneziaVPN/client — гляньте, что там за бинарник

Смотрите вывод. Скорее всего вылезет что-то про Qt/платформу — тогда запуск с явным указанием Wayland:

sh
QT_QPA_PLATFORM=wayland /opt/AmneziaVPN/AmneziaVPN

Если и так молчит — попробуйте QT_QPA_PLATFORM=xcb (через XWayland). Один из двух заведёт окно. Какой сработает — тот и пропишем в автозапуск. Покажите вывод ls /opt/AmneziaVPN/ — назову точный бинарник.

Клавиши громкости не работают — а мышкой из меню noctalia громкость меняется. Это ожидаемо: сами по себе клавиши XF86AudioRaiseVolume и т.п. niri не обрабатывает, пока вы не повесите на них действие. Их надо привязать — и лучше сразу к IPC noctalia, чтобы всплывал её OSD с громкостью. Добавьте в binds { } вашего config.kdl:

kdl
    XF86AudioRaiseVolume  allow-when-locked=true { spawn "noctalia" "msg" "volume-up"; }
    XF86AudioLowerVolume  allow-when-locked=true { spawn "noctalia" "msg" "volume-down"; }
    XF86AudioMute         allow-when-locked=true { spawn "noctalia" "msg" "volume-mute"; }
    XF86MonBrightnessUp   allow-when-locked=true { spawn "noctalia" "msg" "brightness-up"; }
    XF86MonBrightnessDown allow-when-locked=true { spawn "noctalia" "msg" "brightness-down"; }

Сохраните (niri перечитает на лету) — и физические клавиши оживут, с красивым OSD от noctalia. Кстати, noctalia msg brightness-* заодно даст управление яркостью экрана теми же Fn-клавишами.

Иконок в терминале нет, хотя шрифт сменился. Значит Hack Nerd Font не установился под этим именем — иконки берутся именно из Nerd-варианта. Проверьте, что реально стоит:

sh
fc-list | grep -i nerd

Если пусто или нет «Hack» — имя пакета/шрифта другое. На Void Nerd Fonts часто ставятся как nerd-fonts-ttf, а внутри имя может быть, например, Hack Nerd Font Mono или JetBrainsMono Nerd Font. Возьмите точное имя из вывода fc-list и впишите его в foot.ini. Например, если fc-list покажет JetBrainsMono Nerd Font — тогда font=JetBrainsMono Nerd Font:size=12. Имя должно совпадать до буквы.

Ошибка starship init bash — «syntax error, key:value pair has no value». Вот это ключевая подсказка: такая ошибка — не от bash. Bash так не ругается. Это ругается foot, читая свой foot.ini. Похоже, вы случайно вставили строку eval "$(starship init bash)" не в ~/.bashrc, а в ~/.config/foot/foot.ini — а foot ждёт там строки формата ключ=значение, и подавился. Проверьте:

sh
cat ~/.config/foot/foot.ini

Если увидите там строку про starship — уберите её оттуда, она должна быть в ~/.bashrc:

sh
echo 'eval "$(starship init bash)"' >> ~/.bashrc

Затем откройте новый терминал. И проверьте, что starship реально установлен: which starship.
